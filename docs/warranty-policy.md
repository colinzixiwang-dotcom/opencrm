# 可配置质保策略（5186）

## 文档依据与适用范围

- [中台系统开发 PRD V1.1](https://zuvi.sg.larksuite.com/wiki/F3Ykw1TC9i4kBrkz3UdlX4bXgYg)，解析后的文档 PTwQd98wooUflJxKR9bl3O9rgFh，读取版本 741：第 9 节为总体要求。
- [售后 CRM 项目业务确认清单（Phase 1）](https://zuvi.sg.larksuite.com/docx/I1Tndfx8zonbavxEMlJlCx2Aglh)，读取版本 1456：B-501/B-502 的业务备注明确新机起点为激活日与签收后 14 天的较早日期，期限一年；独立喷头从签收次日起保，1080 三个月、3200 六个月。
- [现有实现原始依据](https://zuvi.sg.larksuite.com/docx/VAdIduVsioO8m7xGpE1ljIUogwd)，读取版本 443，附录 B。原有 `docs/rma.md` 已引用该文档，因此原有一年／14 天规则有文档出处。确认清单仍保留“待确认”模板字样，本次采用其中具体业务备注，并在规则中保留出处。

新机通用条款分别落为 Halo 整机、ColorBox 整机规则。未发现 Halo 普通配件、ColorBox 染剂耗材期限，二者建类型及待确认规则，期限为 0、禁用，不代表零天质保或自动豁免。打印头条款不套用于染剂。翻新、退货、待匹配 SKU 不授予新机规则；具体排除清单见配置清单。整机套装按现有整机 SKU 归属处理，不能据此推定套装内每个配件的独立权益。

## 管理员配置

售后配置 → 质保规则：默认列表对比类型、期限、起保方式、适用范围及状态；点击编辑后仅展开一条规则，适用 SKU 支持编号／名称搜索和勾选。类型管理及默认宽限参数收在“类型及默认设置”，保存按钮提示未保存修改。原工作区设置不再提供质保入口。配置项包括类型 ID/名称；规则名称、类型；自然月或天数；起保方式（激活与签收宽限取早、签收日、签收次日、付款日、激活日）；宽限天数、额外后延天数；证据要求；SKU、市场、平台范围；出处；启用状态。商品详情选择所属质保类型。类型和规则属于售后策略，商品仅持有类型身份引用，共享契约不持有存储。

明确“不做期限校验”必须配置启用的时间豁免规则；它仍受原单、SKU 适配、审批和方案限制约束。未配置、规则禁用、缺证据、多条同优先级规则冲突都会阻止依赖质保的方案。日期按业务时区的日历日处理，自然月在月末夹取；现有结束日比较语义保留。起保日尚未到达也不会判定为在保。

规则 SKU/市场/平台条件全部匹配；更具体的条件优先，同分冲突阻断。保存使用预期版本防止覆盖，既有 RMA 保存其评估和规则快照，修改策略不改写历史。

## 已实现与后续边界

这些是受约束的参数配置，不是任意脚本规则引擎。日期及证据目前由客服填写，不会自动向 MES 获取激活记录。B-503 维修暂停、B-504 换货继承需要设备履历和暂停区间模型，目前尚未自动实现；不能把替换机当新购买设备重新评估来模拟继承。按客户等级、故障、次数的权益规则、人工修正审批和延保也不在此次实现范围。审批本身不自动绕过质保。

初始配置通过现有带版本和审计的 API 写入，不直接修改数据库；商品分类、兼容关系、补发审批标志保留。没有创建 RMA 或调用 ERP 写接口。实际应用前后及排除原因记录在 `warranty-configuration-2026-10-27.json`，不包含客户或订单个人信息。

## 验证

单元测试覆盖起保方式、自然月月末、按天、后延、证据要求、待确认及豁免、类型引用约束。浏览器测试覆盖配置持久化、中英及手机布局、版本冲突、历史快照及 RMA 原子拒绝；另运行商品和马邦回归。现场只调用配置 API 和只读评估，不创建业务单据。
